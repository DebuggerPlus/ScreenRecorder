# Отчет о реализации захвата звука в ScreenRecorderWpf

## 1. Архитектура захвата звука
Захват звука реализован в модуле `ScreenRecorder.Infrastructure.Audio` с использованием библиотеки **NAudio**. Основной класс — `WasapiAudioCapture`, который управляет жизненным циклом записи аудио.

## 2. Источники звука и методы захвата
Система разделяет источники на две основные категории для обеспечения максимального качества и минимальной задержки:

### А. Системные звуки (Loopback)
*   **Устройства:** Динамики, наушники, виртуальные выходы.
*   **Метод:** `WasapiLoopbackCapture`.
*   **Особенности:** Захватывает то, что слышит пользователь. Использует WASAPI в режиме Loopback. Реализовано заполнение тишины (Silence Padding): если в системе нет звуков, в файл записываются пустые байты (нули), чтобы сохранить синхронизацию с видео.

### Б. Входные устройства (Микрофоны)
*   **Устройства:** Встроенные микрофоны, USB-микрофоны, Bluetooth-гарнитуры, виртуальные микрофоны (iVCam).
*   **Метод:** `WasapiCapture`.
*   **Особенности:** Ранее использовался `WaveInEvent`, но он вызывал помехи на сложных устройствах. Переход на `WasapiCapture` позволил работать с аудиоданными напрямую через Windows Audio Session API.

## 3. Проблема захвата с e2eSoft iVCam и ее решение
**Проблема:** При записи голоса через iVCam (телефон как микрофон) наблюдались значительные помехи, треск и искажения.
**Причины:**
1.  **Эмуляция:** Старый интерфейс `WaveInEvent` вносил задержки и некорректно обрабатывал буферы данных, приходящие по сети от телефона.
2.  **Несоответствие форматов:** Попытка принудительно установить формат 48кГц на устройстве, которое работает в другом режиме, приводила к потере пакетов.

**Решение:**
1.  **Использование Native WASAPI:** Переход на `WasapiCapture` позволил приложению запрашивать данные в том формате, в котором их отдает драйвер iVCam.
2.  **Низкая задержка:** WASAPI работает ближе к ядру ОС, что критично для сетевых аудио-потоков, где стабильность буфера имеет решающее значение.

## 4. Синхронизация
Для всех источников реализована жесткая привязка к системному времени (`Stopwatch`).
*   Если данные приходят слишком медленно — вставляется тишина.
*   При остановке записи метод дожидается полной финализации файла (`TaskCompletionSource`), что исключает повреждение заголовков WAV.
