# Обработка видео: окно шумоподавления

Окно **Process Video** (кнопка в боковой панели главного окна) обрабатывает **готовый файл**:
шумоподавление с настройками, эквалайзер, уровень. Запись оно не трогает — всегда пишет новый файл.
Видео-поток копируется без перекодирования, перекодируется только звук, поэтому прогон быстрый
(18 с видео 1080p, живой звук → ~4 с на машине владельца; 57 с → 15 с).

## Настройки по умолчанию

По умолчанию (чистая установка, сброс, отсутствие `settings.json`) стоят **рабочие настройки фильтрации** —
рецепт «Fan + voice (RNN)»: срез снизу 100 Гц + нейросеть rnnoise, `mix=1`:

```
highpass=f=100:poles=2,arnndn=m=models/rnnoise/bd.rnnn:mix=1
```

Это значит, что окно сразу готово к работе: не нужно ничего включать руками, «Process the whole file»
уже чистит фоновый шум и гул. Так же настраиваются:

- поля класса `NoiseReductionSettings` (`HighPassHz = 100`, `RnnEnabled = true`);
- `NoiseReductionSettings.CreateDefault()` = `Recipe("Fan + voice (RNN)")` — используется при сбросе;
- разовая миграция `VideoProcessingSchema 0 -> 1` (`SettingsService.MigrateVideoProcessing`): если в сохранённых
  настройках шумоподавление было полностью выключено, оно заменяется рабочим рецептом (пути вход/выход сохраняются),
  и результат сразу пишется в `settings.json`, чтобы миграция не повторялась при каждом запуске.

Полезно знать:

- `NoiseReductionSettings.CreateEmpty()` — **всё выключено**. На этом строится рецепт «All off» и замеры «до/после»
  (сами рецепты тоже начинаются с пустой базы, чтобы не зависеть от дефолтов класса).
- Предупреждение **над кнопкой Process**: жёлтая плашка пишет причину, если нажать нечего —
  «входной файл не выбран», «входной файл не найден: <путь> — файл удалили или перенесли»,
  «ни один блок обработки не включён». Плашка видна всегда, когда обработка не даст результата.
- Каждый отказ (`Process` без входного файла, без выходного, перезапись отклонена) и сам прогон пишутся
  в лог приложения: `<папка exe>\logs\log_YYYYMMDD.txt`. Если кнопка «ничего не сделала» — смотрите лог.

## Что внутри

Цепочка фильтров ffmpeg собирается в `VideoProcessingSettings.BuildFilterChain()`:

```
highpass -> lowpass -> afftdn (спектральное) -> arnndn (нейросеть для речи) -> agate (гейт)
        -> equalizer (пресет) -> volume (gain) -> loudnorm / alimiter / speechnorm
```

Каждый блок включается отдельно и настраивается (всё сохраняется в `settings.json`, поле `VideoProcessing`):

- **обрезка спектра** — `highpass` 0…300 Гц, `lowpass` 0…20 кГц: гул вентилятора и рокот живут ниже 150 Гц;
- **спектральное (afftdn)** — `nf` уровень шума, `nr` глубина подавления, `rf` остаточный уровень,
  `tn`/`tr` отслеживание шума и остатка, `nt` тип шума. Ключевой параметр — `nf`: кнопка
  **Measure noise floor from the file** измеряет его сама (AudioAnalyzer) и подставляет;
- **нейросеть (arnndn)** — модель rnnoise `models/rnnoise/bd.rnnn` (образец обучен на «голос + общий шум»),
  параметр `mix`. На живой записи с вентилятором это самый сильный инструмент;
- **гейт (agate)** — давит шум в паузах: порог, ratio, глубина подавления;
- **эквалайзер** — 10 полос, те же пресеты, что в Audio Settings;
- **уровень** — gain, `loudnorm` до -16 LUFS / `alimiter` / `speechnorm`.

Кнопки-рецепты («Fan / hum», «Fan + voice (RNN)», «Voice, quiet room (RNN)», «Pauses -> silence (gate)»,
«All off») просто заполняют настройки — дальше всё можно править руками. «All off» — полная копия звука
без обработки: чтобы услышать, что именно изменила цепочка.

## Проверка без UI (главный инструмент)

1. Самотест цепочки — синтетический ролик (картинка + «голос» 300 Гц + гул 50 Гц + розовый шум) и проверка по уровням:

```
dotnet run --project tools\VideoProcessingSelfTest -c Release
```

Код возврата 0 = все проверки прошли. Измеряет реальные цифры: гул, голос, уровень шума, пик, длительность.
Есть отдельные проверки дефолтов: чистые настройки должны давать ровно рабочую цепочку
(`hp100 + rnn`), совпадать с `CreateDefault()`, а рецепт «All off» — пустую цепочку.

2. Headless-прогон самого приложения (окна не открываются, отчёт — `process_result.txt` рядом с exe):

```
ScreenRecorder.App.exe --process-video <in> <out> [recipe=<имя>|hp=150 spec=1 nf=-40 amt=16 rf=-70 rnn=1 gate=1
                                                 gain=0 norm=off|loudness|limiter|speech eq=off|<пресет>
                                                 copy=0|1 crf=20 preset=medium kbps=192 container=mp4|mkv ss= t=]
```

Ключи без параметров трактуются как «по умолчанию»: `hp=100 rnn=1` — то же, что и в окне.

3. `ScreenRecorder.App.exe --dump-settings` — печатает эффективные настройки (в т.ч. строку `filters:`)
   и пишет `settings_dump.txt` рядом с exe, не открывая окна. Это надёжнее `--dump-config`, который
   в headless-режиме может ждать UI-поток и висеть.

Осторожно: в headless-режиме приложение нельзя останавливать на UI-потоке — запуск идёт через
`Task.Run(...).GetAwaiter().GetResult()`, иначе continuation ждёт диспетчер и процесс висит.

## Измеренные результаты на живых файлах

Вентилятор + речь, 18 с, 1080p (первый файл, `hp=100 rnn=1` — это и есть дефолт):

| вариант | шум в паузах (p10) | громкие 5 % | полоса 40–200 Гц |
| --- | --- | --- | --- |
| исходник | -46.5 dBFS | -24.4 dBFS | -56.7 dB |
| `hp=100 rnn=1` | **-77.8 dB (-31.3)** | -26.4 dB (-2.0) | **-93.5 dB (-36.8)** |
| `hp=150 spec=1 nf=-40 amt=18 rf=-70` | -58.0 dB (-11.5) | -25.4 dB (-1.0) | -72.7 dB (-16.0) |

Вентилятор + речь, 57.5 с (свежая запись, дефолтная цепочка, окно 12 с на 0:31):

| вариант | паузы (p10) | речь (p95) |
| --- | --- | --- |
| исходник | -46.2 dBFS | -19.0 dBFS |
| `hp=100 rnn=1` | **-68.9 dB (-22.7)** | -20.9 dB (-1.9) |

То есть дефолт убирает шум в паузах на ~23–31 dB, а речь почти не трогает.

## Что проверено, а что нет

- Проверено кодом и ffmpeg: сборка фильтров, дефолты (чистые настройки = рабочая цепочка), все режимы,
  предпросмотр, копирование видео, ошибки (нет файла, вход = выход), нейросеть, прогресс, отмена,
  отчёт CLI, живой файл до/после.
- Не проверялось глазами: сам XAML-окно (кнопки, слайдеры, жёлтая плашка) — нужен визуальный проход владельца.
